TYPES OF SCHEMAS ...
STAR SCHEMA       --> One center fact table which is referenced by all dimension tables [ only one center ]
SNOW FLAKE SCHEMA --> One center fact table which is connected to some tables and that tables are also centre for some connected tables to it 
                      Like a hierarchy ...


#---------------------------------MANAGING RELATIONSHIPS---------------------------------------#


1. ORDERS AND RESTAURANT TABLE ( on Restaurant_ID )


Cardinality------------------
For one order      --> one Restaurant_ID [ONE]
for one Restaurant --> multiple Orders   [MANY]


Direction---------------------
direction --> from restaurant to orders

Query to think while thinking arrow direction logic...
"View all orders for Restaurant ID 101"

Now in restaurant id first ID=101 will be selected and now to lookup orders for this reestaureant id 
we need arrow i.e data tranfer from current(restaurant table) to order table to access all orders for ID=101
So direction --> from restaurant to orders ( as a restaurant has multiple orders )

If arrow direction is reversed , then first restaurant id =101 will be selected but the path from restaurant
to order table is blocked so we cant filter orders just for id=101 so the answer will be sum of all orders
from all restaurant id ( not only 101 )
